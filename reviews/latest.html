Claude Code配套4套Agent Harness横评

外部体验普遍指向：Harness 胜负主要取决于约束设计、上下文隔离与集成成本。

查看原始测评

观察：知乎作者在拆解 Claude Code Harness 实践时观察到，给 Agent 过大的可行动作空间会明显增加失败率，反而需要先人工把任务方向和基础约束铺好，Agent 后续执行才更稳定。

改变：这意味着团队在横评不同 Harness 时，不能只看“自动化程度”，还要看谁更能收缩 action space、把任务拆解和前置约束做扎实，否则同一真实任务下结果波动会很大。

边界：代价是前期要人工设计流程和边界，不适合希望“零配置直接放手跑”的使用场景。

来源：知乎《Claude Code 源码蒸馏 - Harness Engineering 实践记录》

观察：DEV Community 的第三方工作流分析认为，Superpowers、gstack、GSD 三者并不是简单替代关系：gstack 更偏思考与评审，GSD 更偏上下文/规格稳定，Superpowers 更偏构建阶段能力增强。

改变：对用户的真实影响是，选 Harness 不再只是比“谁更强”，而是要按任务阶段搭配：长周期项目更看重上下文稳态，评审密集任务更依赖 review 流程，编码期再考虑 TDD/技能增强。

边界：这种分层组合会增加工作流复杂度，若只是小修小改，收益未必覆盖配置和切换成本。

来源：DEV Community《A Claude Code Skills Stack: How to Combine Superpowers, gstack, and GSD Without the Chaos》

Gemini CLI子代理并行工作流机制

外部观察共识是：子代理提升复杂任务拆解效率，但仍受早期实现成熟度限制。

查看原始测评

观察：青蛙小白在讨论SubAgent时明确指出，Gemini CLI把复杂任务拆给专门子代理处理，形成分层协作而不是单代理串行硬做。

改变：这意味着用户或团队在处理多步骤工程任务时，可以把不同子任务交给不同代理并行推进，减少主代理上下文负担，也更适合组织复杂工作流。

边界：该文同时提到v0.9.0只是引入了SubAgent的基础支持，说明现阶段更像能力起步版，适合尝试任务委派，不代表所有并行协作场景都已成熟可用。

来源：青蛙小白

ComfyUI资产库重写新增预览对比与导出

外部体验普遍指向：价值在工作流浏览、复用与跨环境流转效率。

查看原始测评

观察：独立博主在试玩中提到，ComfyUI 相关增强脚本已能把工作流嵌进截图导出，并支持把别人分享的截图直接拖回界面导入，实际形成了“看图-还原工作流”的闭环。

改变：这让用户分享素材和工作流时不必再单独传 JSON，团队交流、教程复现和案例学习都更直观，工作流导出的价值会直接落到传播和复用效率上。

边界：这类收益更偏向分享和教学场景，对只在本地单人迭代、很少交换工作流的用户提升相对有限。

来源：dg《ComfyUI 试玩指南》

观察：第三方教程总结旧版 ComfyUI 一次只能打开一个工作流很不方便，而工作流管理插件通过左侧列表实现多工作流导入、切换查看、历史版本保存和分类管理。

改变：这说明资产库若原生补上预览浏览、差异对比和导出，真正改善的是多工作流并行筛选、回看和整理的效率，尤其适合模型实验多、版本迭代快的团队。

边界：这类管理能力主要解决“资产多、版本多”的场景；如果用户只维护少量简单工作流，收益不会像重度使用者那样明显。
