MacBook Pro M5 Max离线跑Qwen3.6实测

共识是Qwen3.6已能在Mac本地实用化，但体验强烈依赖机型、内存和推理框架。

查看原始测评

观察：YouTube博主在Apple M5 Max上本地运行Qwen3.6，并直接演示了Agentic Coding与Playwright MCP工具调用，结论是本地推理速度已经快到可支撑连续的代理式编程操作。

改变：这意味着开发者可以把一部分代码生成、页面自动化和工具调用工作流放到离线笔记本上完成，减少对云端额度、网络和隐私暴露的依赖。

边界：片段未给出量化速度、续航或长时间稳定性数据，而且展示场景集中在编码与浏览器自动化，不代表通用任务都同样受益。

来源：Qwen3.6 on M5 Max is INSANE - YouTube

观察：Hacker News用户实测Qwen3.6-27B可在M5 Pro 128GB上运行，且实际只占用约20GB内存，并判断32GB机器也能基本跑起来。

改变：这直接降低了本地部署门槛：很多想离线用Qwen3.6做代码或日常推理的用户，不一定非要上顶配大内存MacBook Pro。

边界：这条经验基于M5 Pro和27B版本，不是对M5 Max或更大模型的完整结论；“32GB可用”也更接近经验判断而非系统化压测。

来源：Hacker News

Claude MCP接入Blender工作流深度实测

共识是门槛下降明显，但效率和成本离稳定生产仍有距离。

查看原始测评

观察：MindStudio 的实测称，Claude 的 Blender MCP 做一个甜甜圈场景耗时约 2 小时，消耗了 Claude Max 月费套餐单次会话约 60% 的 token，而且最终结果仍出现穿模和颜色伪影。

改变：这意味着它更像高成本的探索式辅助建模工具，而不是可直接替代人工的稳定生产流程，团队在正式项目里需要预留明显的试错时间和 token 预算。

边界：对长流程、细节要求高、成本敏感的 3D 生产场景不友好，尤其不适合希望一次生成就可交付的工作流。

来源：MindStudio

观察：YUV.AI Blog 认为 BlenderMCP 把原本需要查 bpy 文档、写命令的流程改成自然语言操作，能直接让 Claude 执行如创建材质球体、调整场景风格这类 Blender 操作。

改变：对不熟 Blender 脚本或 API 的用户，进入门槛明显降低，原本依赖脚本知识的场景搭建和修改可以转成口头式指令驱动。

来源：YUV.AI Blog
