Claude Opus 4.8 外部测评 Claude API / Apifox

Claude Opus 4.8并行代理与诚实度实测

共识是它更适合高预算长任务，价值主要在并行执行与少糊弄。

查看原始测评

观察：第三方上手文章称，Opus 4.8 在 Claude Code 里可通过 Dynamic Workflows 一次任务并行拉起几十到上百个子 agent，主 agent 会在汇总前自检结果；同时作者给出的实测结论是精确度明显提升、honesty 提升约 4 倍，但创作表现仍弱于 4.6。

改变：这意味着开发者和团队在长链路编程、资料整理、代码排查这类可拆分任务中，可以少做人工拆任务和二次校对，把并行执行与结果汇总交给模型本身。

边界：代价是更高的 token 与执行成本，而且该文也指出它并没有同步改善创作型场景，因而不适合把“更诚实/更并行”直接等同于“所有任务都更强”。

— Claude API

观察：Apifox 的工作流分析指出，Opus 4.8 的 `effort` 档位直接决定一次响应里可消耗的推理与工具调用预算，其中 `xhigh` 被明确对应长周期编程和智能体任务，而 Claude Code 里的 Dynamic Workflows 实际被收在 `ultracode` 选项之后。

改变：对实际使用者来说，这不是普通的“模型更聪明”升级，而是要按任务长度和预算主动切换到更重的工作模式，才能释放并行代理能力。

边界：边界也很清楚：这类模式面向运行 30 分钟以上、token 预算更大的任务，短平快问答或低成本场景并不划算。

— Apifox
