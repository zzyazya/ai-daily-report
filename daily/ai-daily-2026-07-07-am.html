Hermes Agent多模型专家协作功能更新

外部观察认为它更像任务编排升级，而非单模型能力跃迁。

查看原始测评

观察：第三方工作流分析指出，Hermes 已通过 ACP 协议把 Claude Code、Codex、OpenCode 这类外部专业 Agent 作为子 Agent 接入，由 Hermes 充当协调层分派任务，每个子 Agent 还能使用不同模型和工具链。

改变：这意味着团队可以把代码、推理、执行等环节拆给不同专长模型处理，而不是让单一模型包办，从而更接近真实团队分工式的 Agent 工作流。

边界：这套方式更适合已有多 Agent 与多工具链的复杂流程，代价是编排层和子 Agent 的接入、协调与维护成本会上升。

— AioGeoLab | GEO优化实验室
外部测评 / 上手体验 SmartScope / Xugj520 / 掘金

OfficeCLI让AI代理可读写Office文件

共识是它把Office操作真正接进了可自动化的AI工作流。

查看原始测评

观察：SmartScope认为OfficeCLI把原本对AI流程很别扭的Office文件处理，收敛成一个开源单二进制工具，能直接编辑Word、Excel和PowerPoint，并给代理返回可视化反馈。

改变：这让团队把“生成内容—修改文档—再检查版面”放进同一条代理工作流里，减少人工打开Office做最后确认的环节。

边界：文章同时强调它有能力边界与限制，更适合结构化编辑和可回看的代理流程，不等于完整替代人工处理所有复杂文档细节。

— SmartScope

观察：Xugj520的分析提到，OfficeCLI除了读写文档，还内置渲染和JSON输出，能把PPT等文件按页生成PNG，供多模态模型逐页复核。

改变：对用AI批量产出汇报、方案或表格的团队来说，这意味着代理不只会“写文件”，还可以把版面截图回传给视觉模型做二次检查，减少格式错误直接流入交付物。

边界：这套价值主要建立在代理或多模态审阅链路上；如果用户只需要手工编辑Office文件，渲染与JSON能力带来的收益会明显下降。

— Xugj520
