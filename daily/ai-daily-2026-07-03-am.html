DSPy优化Datasette Agent SQL提示词评测 Haystack / Prem / ADaSci

DSPy优化Datasette Agent SQL提示词评测

外部经验的共识是：DSPy能系统化优化SQL提示词，但前提是有可验证的数据与评测集。

查看原始测评

观察：Haystack 的上手指南明确把 DSPy 提示词优化写成一个“训练集优化、开发集评估”的流程，说明这类 SQL Prompt 改进不是拍脑袋改文案，而是依赖样本集反复验证效果。

改变：这对 Datasette Agent 这类 Text-to-SQL 工作流的真实意义是，团队可以把 system prompt 调整变成可复现的评测流程，减少只靠人工试几句的主观调参。

边界：代价是必须先准备有代表性的查询样本并做数据划分；如果没有足够贴近真实问题的 SQL 例子，优化结果很容易失真。

— Haystack

观察：Prem 的 Text-to-SQL 教程直接演示了用 `dspy.Signature`、`dspy.Module` 和 `dspy.teleprompt` 搭建并自动优化 SQL 生成链路，外部作者实际观察到 DSPy 可以用于提升 Text-to-SQL Prompt 的实际产出。

改变：对用户而言，这说明像 Datasette Agent 这样的 SQL 代理不必完全依赖手写 prompt，可以把 SQL 生成能力纳入可迭代优化的流水线，从而更快比较不同提示词方案。

边界：这套方法更适合输入输出边界清晰的 Text-to-SQL 任务；如果代理任务混入大量开放式推理或工具编排，单靠 prompt 优化未必就能稳定提升。

— Prem
