Local-Splitter研究七种Coding-Agent降Token策略

共识是先压缩探索成本，比单纯换便宜模型更能省 Token。

查看原始测评

观察：Sperix Labs 观察到，Local-Splitter 把一个本地 3B 小模型放在 Coding Agent 前面后，简单请求可直接本地处理、复杂请求再压缩后转发云端，相当于把“是否值得上云”先做了一次分流。

改变：这会直接改变团队的 Agent 成本结构：日常大量浏览、检索、确认类小请求可以变成零云端 Token，只有真正复杂的推理步骤才消耗大模型预算。

边界：它并不是完全替代云模型的方案，复杂任务仍要上云，只是减少无效上下文和前置探索带来的 Token 浪费。

— Sperix Labs
外部测评 / 上手体验 WaveSpeed 博客

DeepSeek v4对比Claude Opus编程实测

共识是两者强项不同：一个偏大上下文改动，一个偏稳健小补丁。

查看原始测评

观察：WaveSpeed 的编程对比文提到，在需要跨多个模块处理大规模 diff 时，DeepSeek V4 在长上下文下表现更稳；而 Claude Opus 4.5 的优势是补丁更克制、按要求给最小修改，并且在要求先做三步计划和 dry-run 时更少“编造步骤”。

改变：这意味着团队若经常处理跨文件重构、长代码上下文任务，DeepSeek V4 可能更适合做大范围改动；但如果工作流强调小步提交、可审查补丁和先规划后执行，Claude Opus 更贴近日常工程协作习惯。

边界：这篇材料聚焦作者主观上手与编程工作流体验，且对比对象是 Claude Opus 4.5 而非新闻中的 Opus 新版本，因此更适合当作真实使用倾向参考，不足以单独证明绝对性能胜负。

— WaveSpeed 博客
