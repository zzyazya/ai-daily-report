观察：Narek Maloyan 实测把 `Qwen 3.6-35B-A3B` 作为 Mac mini M4 16GB 的日常本地模型常驻使用，配合 Ollama 可一键启动、提供 OpenAI 兼容接口，且工具调用可正常工作。

改变：这意味着对个人开发者或小团队来说，35B 级 Qwen 已不只是“能跑起来”，而是可以直接接入现有 OpenAI API 工作流，作为本地编码/代理助手长期在线使用。

边界：这篇体验基于 16GB 机器和 Ollama 常驻场景，证明的是可用性与工作流顺滑度，不代表在高并发、超长上下文或极限吞吐下也有同样表现。

— Narek Maloyan Blog

观察：InsiderLLM 在 2026 年 Mac 本地模型测试中认为，Mac mini M4 Pro 48GB 跑 `Qwen3.6-35B-A3B` 是“让本地 AI 值得用起来”的主力组合，但同模型下其单 token 速度仍慢于 Mac Studio M4 Max 64GB。

改变：对打算买 Mac 做本地推理的用户来说，这把 35B-A3B 定位成了 M4 Pro 48GB 的现实甜点位：足以承担日常本地问答/代码助手，而不必一开始就上更贵的 Studio 级配置。

边界：代价是吞吐上限仍受限于机器档位；如果团队更看重更快响应、更重模型或更高并发，Studio 64GB 以上仍有明显性能优势。

— InsiderLLM

风险提醒

容易误读看到 AgentBeats、WorkflowPerturb、DualGauge、EvoMemBench、CODA-BENCH、RetailBench 等一批新基准/评测论文，就认为 Agent 评测标准已经收敛，开发中可以直接据此比较方案优劣并指导上线决策。
正确理解这些成果大多还是 arXiv 阶段的方法、基准或框架提案，覆盖任务、指标、成本假设和失败定义并不统一，彼此结论通常不能直接横向对比。尤其像“预算约束下Web Agents记忆模块值不值”和“十三种架构下Agent Memory遗忘研究”这类结果，强依赖具体 token 预算、任务分布和记忆实现，不能外推为通用工程规律。
建议建议先把 AgentBeats、DualGauge、RetailBench 等当作补充评测集做小规模复现实验，再结合你自己的真实业务任务、成本和安全指标决定是否采纳。

边界：文章同时提醒FP8与GGUF不是同一套量化逻辑，不能把Q2-Q8简单类比成FP8的替代档位；如果团队更在意数值稳定性或横向对比一致性，需单独复测。

边界：这类结论更偏向“Q4以上可接受”，并不等于Q2也能保持同等画质；如果目标是极限保真或后续重剪辑，仍需对低量化档位单独验画。
